01

The victim is a 48-bit truncated LCG

staten+1 = (a · staten + b) mod 2⁴⁸  ·  a = 25214903917, b = 11

java.util.Random — the same generator behind Minecraft's world RNG, Apache Commons RandomStringUtils, and unseeded new Random() token generation — advances a 48-bit state by one linear step per call and hands back only the top bits. nextFloat() leaks the top 24; a power-of-two nextInt() leaks its top log₂(bound).

Each leaked call pins the hidden state to an interval. Stack a few and the constraints become a lattice: recovering the state is a closest-vector problem the Babai round-off solves in microseconds. This is the Randar attack, generalised. The lab pins its correctness to the published vector — three nextFloat MSBs crack back to an exact internal state:

The edge is a band, not a line

at n·k = 48 the leak stops distinguishing every state

Right at 48 leaked bits, the observation no longer picks out a single state — several java.util.Random states produce the identical leak. The enumeration stays complete (the true state is always in the set), so the honest answer is a range of candidates, never a collapsed guess.

04

What governs the boundary

three hypotheses, confirmed on the lab's own data

H1 · total bits

It's n·k vs 48

Unique recovery is governed by total leaked bits against the 48-bit secret — not by how the bits are split across calls.

0% at n·k ≤ 40 · 39% at 48 · 100% for n·k ≥ 60
H2 · round-off

Uniqueness is the limiter

The Babai round-off margin ‖M·e‖∞ never crosses its 0.5 safety line anywhere on the grid — so it's information, not arithmetic, that bounds recovery.

peak margin 0.477 < 0.5 across all 49 cells
H3 · leak shape

Odd bounds leak less

Same raw bits, wrong shape: nextInt(odd) gives a residue class the round-off lattice can't consume — it needs an HNP attack instead.

see the leak-model panel below ↓

Calibration against an exact oracle. An ideal-hash null predicts P(unique) = exp(−2^(48−n·k)). It lands inside a 95% Wilson interval for 46 of 49 cells — perfectly across the over- and under-determined regions (44/44). The only three misses are exactly the edge cells, where the structured LCG departs from an ideal hash. That's the phenomenon, caught by the calibration, not a modelling error.

05

H3 in three leak models

raw bits leaked vs bits usable by the round-off lattice · per call, 8-bit width

"Usable structure" is measurable: the Shannon entropy of one observation is the raw information it carries; whether that information arrives as an interval decides if the round-off box-CVP can consume it. Two ways to leak less usable structure than a clean top-bits leak — and both real Java idioms hit them.

top_bits(8)

interval (prefix)

raw bits7.99
box-usable7.99

The Randar leak. Every bit lands as an interval the lattice reads directly.

nextInt(odd 255)

residue-class (mod odd)

raw bits7.99
box-usable0.00

Same information — but a residue mod an odd bound is coprime to 2⁴⁸. Round-off can't touch it; this is the elttam / RandomStringUtils case (HNP).

bit_length(nextInt)

interval (leading-bit; starved)

raw bits1.99
box-usable1.99

Right shape, starved: ~2 bits per call whatever the bound. The Minerva end — needs many observations.

07

The fold-in: a repoauditor detector

a shared, predictable generator crossing a trust boundary — invisible to SAST & CVE feeds

The point of the harness is a seam. Weak-RNG token generation is a real class of bug that dependency scanners and CVE feeds can't see — nothing is vulnerable in the CVE sense; a safe primitive is simply used across a trust boundary. The lab folds into repoauditor as a weak_rng_adapter in two halves.

✓ built · reuses validated cracker

demonstrate

demonstrate_from_msb24 turns a suspected weak-RNG site into a reproducible next/prev-token recovery — the same round-off path pinned by the Randar vector. It emits a RecoveryDemonstration, a corroborating source for severity licensing. It never sets severity itself.

◐ proposed · OPT-036 · pending merge

detect

detect_in_source finds the idioms in code — built inside repoauditor against its live retrieval layer and CandidateFinding contract. It proposes a conservative initial severity; repoauditor's own normalize/adjudicate owns any upgrade.

Honest baselines, throughout. Recovery from the odd-bound and bit-length leaks is a disclosed capability gap — those need a Hidden-Number-Problem lattice, not this lab's round-off box — recorded explicitly, never faked. The whole harness is offline: it attacks a generator it instantiates itself. No network target, no third-party system in scope.
